# Server idle via in-page network instrumentation

EvidenceFactory Aggregation must never start the next editor action until prior server work has finished, and must not use fixed sleeps. We decided that **application idle** means zero pending application `fetch` / `XMLHttpRequest` (plus WebSocket or SSE activity if Phase 1 finds them), tracked primarily by in-page network instrumentation, with loading indicators only as secondary checks and a short settle rule so chained requests count as one burst. Playwright request/response events alone are allowed as a simplification only if Phase 1 shows every relevant call is visible that way without gaps; UI-spinner-only waiting was rejected as too weak for an app that hits the server after nearly every action. Reliability outranks speed: overlapping actions are forbidden.
